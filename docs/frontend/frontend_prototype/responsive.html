Responsive behavior

Device-specific layout and accessibility contract

Desktop, tablet, mobile

Responsive by composition, not by omission

The HomeOps prototype keeps the same operational hierarchy on every device. Layout changes should alter grouping and density, never remove authority, context, or required actions.

Desktop · 1200px+

Persistent command rail

Left navigation remains visible. Dashboard uses multi-column panels. Timeline, alerts, and insights can sit beside each other.

Stable sidebar: 240–280px
Content max width: 1200–1500px
Cards: 2–4 column grids
Tablet · 721–980px

Progressive collapse

The navigation rail narrows, multi-column cards collapse to two columns, and content maintains readable padding.

Grid changes: 4 → 2 columns
Keep panel order intact
Allow action rows to wrap
Mobile · ≤720px

Drawer and reading order

Navigation becomes a drawer. Header actions stay reachable. Every card stacks in the order a household member needs to act.

One-column cards
Menu is keyboard reachable
No hover-only behavior

Responsive acceptance checklist

Use this when implementing or reviewing each route.

NavigationDesktop rail, mobile drawer, visible active route, escape/close behavior.
TypographyText remains legible at compact/default/large scale; no clipped labels or overflowing buttons.
Data densityLists become stacked readable rows; tables receive horizontal scrolling or a mobile card representation.
ControlsActions wrap, retain accessible names, and never depend on hover to reveal meaning.
AccessibilityKeyboard focus, reduced motion, contrast, live status, and touch targets are part of the layout.
